# Index des verdicts

Le livrable partageable de l'exploration outillage/pratiques du
[plan de solidité technique](../../PLAN_SOLIDITE_TECHNIQUE.md) (Lot 0.3) :
« j'ai essayé ~25 outils de qualité sur un vrai projet, voilà lesquels ont
trouvé quelque chose ». Un rejet argumenté vaut autant qu'une adoption —
souvent plus, parce que personne ne publie ses rejets.

Une entrée par expérience close, gabarit dans [`TEMPLATE.md`](./TEMPLATE.md),
rédigée via `/log-experiment`.

| [001](./EXP-001-audit-commentaires-heuristique-git-blame.md) | Heuristique `git blame` (staleness) | Audit de commentaires (Lot 6.1) | Adopté (comme filtre) | 329/~5 200 blocs présélectionnés (écarts jusqu'à 379j) ; 5 vérifiés à la main, 5/5 vrai décalage temporel mais 0/5 péremption réelle — bon proxy pour « à relire », mauvais pour « c'est faux » | ~1h30 |

| [003](./EXP-003-couverture-runtime-e2e.md) | `coverage.py` + Istanbul (`vite-plugin-istanbul`) sous Playwright | Couverture *runtime* e2e (Lot 6) | Adopté (script manuel, pas de gate CI) | Backend 34 % exécuté en e2e vs 91,56 % unitaire ; frontend 63 % vs 87,05 %. `api/domain/polity/*` (2 813 lignes, ~19 % du backend) : 0 % e2e, ~99 % unitaire, aucune route enregistrée. `/simulation/compare` : page retirée du routage, backend + hook frontend toujours testés à 100 % unitaire, invisibles à `knip` (import satisfait par leur propre test) | ~5h |
| [004](./EXP-004-regression-visuelle-playwright-screenshots.md) | Playwright `toHaveScreenshot` (Docker épinglé) vs Lost Pixel | Régression visuelle (Lot 7) | Adopté (gate CI, job séparé) | Lost Pixel écarté sans essai (dépôt archivé, équipe partie chez Figma, avril 2026). Détecteur vérifié contre une régression injectée : une tolérance `maxDiffPixelRatio: 0.01` choisie « par prudence » laissait passer un marqueur mal coloré (0,07 % des pixels) — supprimée, la même injection échoue alors proprement (303px, ratio 0,01). `ParliamentCanvas` sans backend affiche un état d'erreur permanent, pas une carte légèrement différente — backend ajouté au job CI. Un flash de légende intermittent (~1 échec/3 runs) tracé à un race React Strict-Mode-dépendant, corrigé par une attente de son cycle de vie fixe. 8/8 runs natifs + 6/6 Docker, zéro échec. Rebase sur `develop` avant merge : un `testIgnore` de projet écrasait silencieusement celui de la racine (241 tests au lieu de 227, `visual.spec.ts` tournant hors Docker) et le script Docker laissait des fichiers `root` dans le dépôt — deux pièges trouvés et corrigés en rejouant la suite par défaut après rebase, pas en supposant le comportement inchangé | ~5h30 |
| [005](./EXP-005-form-lock-profiler-invariant-and-bundle-budget.md) | React `<Profiler>` + `size-limit` | Invariant de perf du form-lock + budget de bundle (Lot 8) | Adopté (les deux) | Un plafond en ms absolues sur le 1er rendu React varie ×4,5 entre un run froid et chaud du MÊME code — rejeté, remplacé par un compte de commits (2, déterministe) + un ratio de coût relatif (×5-12 mesuré, gaté à ×3) ; les deux vérifiés contre 3 régressions injectées. Le Profiler React ne mesure jamais le corps d'un effet (calcul de 20M itérations glissé dans un effet : invisible). Budget de bundle : baseline réelle 810,88 kB brotli, gate à 1 MB ; `bundlesize` (>2 ans, abandonné) et `vite-plugin-bundlesize` (mainteneur seul) écartés, `size-limit` adopté — conflit de peer-dependency exacte trouvé en l'installant (le plugin `@size-limit/file@13.0.3` exige `size-limit@13.0.3`, qui a relevé son exigence Node au-delà de Node 20) | ~4h |
| [006](./EXP-006-pytest-benchmark-engine-perf.md) | `pytest-benchmark` | Perf du moteur de vote (Lot 8.1) | Adopté (gate CI bloquant, seuils absolus) | Les 26 méthodes tiennent en <14 ms même au plafond de production (1000 électeurs, 8 candidats) — plafonds absolus 100/500 ms (15-500x la mesure réelle), pas de comparaison à une baseline stockée (`pytest-xdist`, utilisé par la suite normale, désactive silencieusement `pytest-benchmark`). Régression O(n²) injectée en direct sur `get_copeland_winner` : ×290 (3,7 ms → 1101,6 ms), détectée puis confirmée verte après retrait | ~2h |
| [007](./EXP-007-locust-v2-thread-pool-ceiling.md) | Locust | Vrai plafond du pool de threads /api/v2 (Lot 8.2) | Adopté (script manuel, pas de gate CI) | Le rate-limit 120/min (par chemin) ne protège pas le sémaphore partagé de 4 workers CPU-bound (`worker_dispatch.py`) : à 8 utilisateurs Monte-Carlo concurrents, latence médiane 3,0 s → 7,2 s → 14,0 s → 25-30 s en doublant la concurrence, **zéro 429/503** sur toute la plage testée — la dégradation se voit d'abord en latence, jamais en erreur. Piège d'environnement (port déjà occupé par un process tiers) quasi identique à celui d'EXP-003, retrouvé indépendamment | ~4h |
| [008](./EXP-008-cosign-slsa-provenance-signing-scope.md) | cosign + `actions/attest-build-provenance` | Signature d'images + provenance SLSA (Lot 9) | Adopté (périmètre réduit — SBOM signé, pas l'image) | Aucune des deux images Docker n'est jamais publiée (`load: true` en CI, `release.yml` ne construit ni ne pousse rien) — signer « l'image » au sens OCI natif n'a aucune destination, donc c'est le SBOM (le seul artefact réellement publié) qui est signé (`cosign sign-blob`, keyless) + attesté en provenance SLSA. `slsa-framework/slsa-github-generator` confirmé non maintenu depuis ~février 2025 par son propre README, écarté au profit d'`actions/attest-build-provenance`. Vérifié en direct en local (vraie image construite, vrai SBOM généré par syft, signature + sabotage + attestation) : `--check-claims=false` sur `cosign verify-blob-attestation` désactive silencieusement la vérification de hash du sujet — un faux positif trouvé en testant le cas négatif, pas en lisant la doc | ~1h30 |
| [009](./EXP-009-osv-scanner-vs-trivy-overlap.md) | OSV-Scanner vs Trivy | Recouvrement des bases de vulnérabilités (Lot 9) | Adopté (informational, local + CI) | Détecteur vérifié sensible (2 paquets sciemment obsolètes, `urllib3==1.26.4`/`Jinja2==2.4.1` → 18 CVE réels chacun) puis exécuté pour de vrai sur les dépendances de ce dépôt : **0 vs 0**, cross-vérifié par un troisième outil (pip-audit, 0) — écart nul mesuré, pas supposé. Deux pièges d'environnement diagnostiqués avant contournement : la source de données par défaut (`deps.dev`, gRPC) timeout dans cette session sandboxée alors que l'API REST du même service répond normalement ; le mode récursif par défaut trouve silencieusement 0 source de paquets depuis un *worktree* git (fonctionne en dehors, ou via `-L` explicite dans le worktree) | ~1h45 |
| [010](./EXP-010-zap-baseline-dast.md) | OWASP ZAP (`zap-baseline.py` / `zaproxy/action-baseline`) | DAST — comportement HTTP réel (Lot 9) | Adopté (gate CI non-bloquant, job dédié nightly + push:develop) | App sans aucun header de sécurité HTTP (vérifié par `curl -I`) : 9 alertes réelles par cible (CSP, Permissions-Policy, anti-clickjacking, SRI, Cross-Origin-*-Policy), invisibles à Semgrep/CodeQL. Mode `zap-api-scan.py` piloté par `openapi.gen.json` écarté (actif, « attempt exploitation » — hors du périmètre passif que l'item demande). Spider « moderne » (`-j`, navigateur headless) bloqué indéfiniment (~59 min, tué à la main) — retiré ; le spider traditionnel seul découvre déjà 25 URLs (tous les assets référencés en HTML brut) en 28,6 s. Cycle complet injection/détection/retrait vérifié trois fois sur `X-Content-Type-Options` (WARN-NEW 9↔8, PASS 58↔59) | ~3h30 |
