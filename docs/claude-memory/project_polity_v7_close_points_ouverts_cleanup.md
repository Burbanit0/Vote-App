**v7 closed (PR #227)**: the acceptance run (rounds=1 vs rounds=3 coalition negotiation, §3.4 Cas 2) confirmed parity and extended Lot 3's live-spike finding (zero observed revisions) to real journaled data. `run_v7_acceptance.py`'s own `summarize()` had a real bug — accepted `--results` but never wrote the file — fixed; verified the other four acceptance scripts didn't share it. Roadmap v0-v7 (`polity-simulation-design-v2.md` §13) is now fully complete and merged into `polity`.

**Points ouverts triage (2026-08-30, PRs #228-231)**: the design doc's 21-item "Points ouverts" list was systematically audited against current code (not assumed accurate) via a Plan-Mode-approved triage into effort groups. Several entries marked "tranché" turned out to be stale — same class of staleness as the v6bis #12 fix from earlier in the week. Resolved/closed:
- #8 (storage), #9 (confidence vote format), #18 (petition concurrency), #20/#21 (vLLM determinism, reframed to Ollama) — doc-only corrections, code was already right.
- #15 (`event_type` stays a string — DuckDB already compresses a 29-value column natively) and #17 (`passive_erosion_weight` stays 0.0) — quick decisions, no code.
- **#1 — rupture candidacy threshold** (PR #228): `attempt_rupture_candidacy`'s probability now scales with `weighted_distance` to the citizen's own affiliated party (`rupture_distance_multiplier=2.0`, pragmatic default, no literature available). **Real finding**: `party_affiliation` is NEVER `None` in practice — `assign_party_affiliation` (population init) always returns a concrete party_id via `math.dist`; only `choose_party` (a different function, legislative vote choice) can return `None`. Don't add a None-guard for `party_affiliation` elsewhere without checking this first.
- **#3 — LLM decision audit sampling** (PR #229): new `scripts/sample_llm_decisions_for_audit.py`. **Real finding**: filter on a truthy `motif` field, not `event_type` alone — `pressure_action` (and potentially others) is written by BOTH the deterministic and LLM paths depending on `config.llm.enabled`; only the LLM path sets `motif` (`run_polity_simulation.py`'s own `motif: str | None = None` default). Also found points ouverts #7 was stale: `llm.rationale_mode` accepts `free_text`/`hybrid` in config but `llm_behavior_engine.py:451-452` raises `NotImplementedError` for anything but `codes` — no raw LLM reasoning is durably persisted anywhere for a successful call, only the coded motif + payload.
- **#4 — party split** (PR #230): closed out of scope. `parties.split_enabled` was parsed but never consumed by any code, and unlike every other point ouvert this project has resolved, no research motivation was ever written for it anywhere. Deleted (same treatment as `candidacy.independent_signature_ratio`, ADR-003), not left reserved.
- **#11 — sortition chamber veto power**: NOT resolved, deferred beyond the current roadmap. **Real finding**: giving the chamber real power requires a "law" concept that doesn't exist anywhere in the model — `legislative_result` is only seat allocation, `chamber_deliberation` (v6b Lot 3) is purely self-referential (each member decides only whether to shift their OWN position, same pattern as `representative_response`). Would be v7-scale work (own decide_*, config/codebook/schema/spike/acceptance run), not a light Lot 1. Documented in the design doc for a future reopening, not silently dropped.
- **v8's "distillation théorique" (§12)**: the term appeared exactly once in the whole project with zero elaboration. Resolved (not just deferred) via reasoning, not evidence: reads as "principled/formalized distillation method," NOT "distill political-science theory into the weights" — grounded in §3.6.0's purpose clause ("stabiliser le contenu dans le cadre du §3.3"), written in the same breath as the fine-tuning mention itself, versus §12 being the only place "théorique" appears with no anchoring context. If it meant theory-injection it would contradict §3.3's explicit no-prescriptive-priors principle, which carries no "except v8" reservation anywhere. Section upgraded 🟡→🟢 in the local design doc. Full fine-tuning chantier (data/method/eval) still unwritten.
